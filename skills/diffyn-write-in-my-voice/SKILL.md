# Write in my voice

Apply the requested editing operation to the supplied writing. Preserve deliberate slang, dialect, humour, technical terms, directness and warmth unless the request changes them. A short or unconventional style is not evidence of low ability.

## Workflow

Identify the intended audience and edit scope from available context. Ask only when a missing fact materially changes the result. Return text the person can use, and briefly explain consequential changes when that helps review.

Check exact quantities, units, dates, names, links, code, quotations, negation, conditions, obligations and uncertainty. Review meaning as well as tokens: “may” and “must” create different obligations. Do not insert apologies, enthusiasm, agreement, consent, disclosure or promises.

If Diffyn is available, compare_protected_details can flag differences between the original and revision. Inspect its coverage and findings; matching protected details does not prove semantic equivalence. check_response_contract may check supplied presentation constraints, not the quality of the writing. Without tools, perform a direct comparison.

## Example

Original: “I cannot do Friday. Tuesday works, if the figures arrive first.”

A clearer version must retain the refusal of Friday and the condition on Tuesday. “Happy to deliver on Tuesday” changes both tone and commitment and is not an equivalent edit.

## Failure handling

If the intended meaning is unclear, retain the ambiguity or ask a focused question. If a shorter version cannot retain a material condition, keep that condition and explain the trade-off. Offer a different draft when the user says the result does not sound like them. Do not send, publish or save personal style preferences without authorization.
