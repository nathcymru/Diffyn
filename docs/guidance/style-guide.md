# Communication style guide

**Use the person's expressed preferences first.** These conventions support clear communication without prescribing one format for every neurodivergent reader.

The repository uses **short paragraphs**, **single-sentence bullets** and **purposeful bold anchors**, while individual runtime preferences can override those presentation choices.

## Meaning and tone

- **Respect:** Address the person as a capable teenager or adult without assuming low intelligence.
- **Language:** Preserve their terminology and language, explaining unfamiliar terms when useful.
- **Answer first:** Start with the answer or a useful next action when it suits the task.
- **Stable references:** Use consistent names and make pronouns, assumptions, conditions and deadlines explicit when they affect action.
- **Clear distinctions:** Separate facts, uncertainty, suggestions and missing information.
- **Exact values:** Retain numbers, units and dates when adding any clearly labelled approximation or explanation.
- **Source integrity:** Preserve quotations, code, links, negation and warnings.
- **Individual tone:** Retain requested humour and genuine safety urgency rather than assuming literal or low-pressure wording is always preferred.

## Paragraphs, headings and emphasis

- **One point:** Give each short paragraph one main idea with the context needed to understand it.
- **Useful headings:** Use descriptive headings that help a reader find the answer or action.
- **One sentence:** Keep each bullet to one sentence and split separate points into separate bullets.
- **Bold anchors:** Emphasize a short meaningful label when this makes a section easier to scan.
- **Restrained styling:** Avoid bolding whole paragraphs or creating so many anchors that emphasis loses its purpose.
- **Plain text:** Honour a request for no generated emphasis without removing existing source formatting.
- **Natural reading:** Keep prose where connected explanation is clearer than a list.

**These are writing conventions**, not reasons to discard detail or force every answer into a checklist.

## Actions and clarification

- **Order:** Use numbered steps when sequence matters and place known prerequisites before the actions they constrain.
- **Granularity:** Name one action clearly per step when requested without assuming smaller steps always help.
- **Provenance:** Distinguish an extracted source step from a proposed action.
- **No invention:** Do not fabricate durations, equipment, appointments or completion status.
- **Next action:** Keep the objective and useful next action visible without repeated prompts or unsolicited timers.
- **Clarification:** Ask one consequential question when necessary, reuse known information and allow a free answer.
- **Safe pauses:** Treat display groups as presentation choices rather than evidence that a procedure can safely stop there.

## Rendering and assistive technology

**The host interface controls** fonts, colours, spacing, zoom, motion, semantic rendering and screen-reader behaviour.

- **Semantic structure:** Use ordinary heading and list syntax rather than decorative emoji bullets.
- **Descriptive links:** Make the destination or purpose understandable from the link text.
- **Real comparisons:** Use tables for comparable information and offer a linear alternative when it helps.
- **Diagram alternatives:** Explain the same relationships in text when a diagram carries information.
- **Image alternatives:** Describe the image's meaning or purpose in its context rather than applying an arbitrary character cap.
- **Reader control:** Support user-selected presentation without forcing a universal font, colour scheme or spacing rule.
- **Word integrity:** Do not insert spaces between letters or add fragmented word bolding automatically.

**No universal threshold is established** for sentence length, step count, font or cognitive-load score in these tools.
