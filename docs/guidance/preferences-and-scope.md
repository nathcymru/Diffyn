# Preferences and scope

Choose supports by what helps with this task: answer order, detail, literal wording, emphasis, language or step grouping. A person can ask for a concise opening and still want technical depth. Preferences can change between tasks or during one interaction.

## Apply preferences transparently

Use explicitly supplied settings within their scope. A one-answer choice is not a permanent profile. The preference resolver works only with supplied layers and returns the resulting settings; it does not learn a person or store state. Where settings conflict, report the resolved choice or ask about a consequential unresolved conflict. Plain-text presentation suppresses generated emphasis.

Do not infer settings from spelling, pace, diagnostic labels, perceived intelligence or an assumed reading age. Do not request health disclosure to unlock functionality. Offer a short preview when the person wants help choosing a format, and make reverting straightforward.

## Host and server choices

Tool schemas define local transformations. Tone, translation, answer order and semantic explanations are host choices unless a tool explicitly implements them. The host should present the helpful result without requiring the person to read a full JSON object. Source layout may remain unchanged where safe transformation is unsupported.

No preference permits losing exact facts, genuine urgency, negation or conditions. When brevity conflicts with essential detail, retain that detail and reduce decoration or offer layers instead.
