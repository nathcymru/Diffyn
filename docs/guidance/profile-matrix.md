# Combined preference matrix

**Choose supports by the task and the person's stated preferences.** This historical resource URI remains available, but its content is organised around needs rather than diagnostic categories. Self-described labels do not select defaults.

| Chosen needs | Possible combination | Trade-off to check |
| --- | --- | --- |
| A quick opening and technical depth | Answer first, then supporting detail | The opening must keep essential conditions |
| Predictable structure and task initiation | Stable section order and a visible first action | Do not make the setup longer than the task |
| Reading comfort and useful emphasis | Short sections with sparse optional anchors | Extra decoration can add clutter |
| Literal wording and warmth | Explicit references with a warm tone | Do not remove requested humour or personality |
| Motor sequencing and fewer navigation demands | Linear steps with stable control names | Keep prerequisite information near the action |
| Numeracy support and precision | Exact values alongside explanations | Do not substitute a vague label for a number |
| Returning after interruption | A supplied resume card and a recorded next action | Stale state must remain visibly uncertain |

## Resolve a conflict

Preserve meaning first. Apply the most specific explicit preference within its stated scope, then use neutral defaults for omissions. Ask a concise question only if the remaining conflict changes useful work. Make format changes reversible and allow more detail or no accommodation.

These combinations are engineering options informed by personalization guidance, not validated clinical prescriptions. Spelling, pace, vocabulary and diagnostic labels do not establish intelligence, capacity or preferred format. See [preferences and scope](https://github.com/nathcymru/Diffyn/blob/main/docs/guidance/preferences-and-scope.md) and the [research basis](https://github.com/nathcymru/Diffyn/blob/main/docs/research.md).
