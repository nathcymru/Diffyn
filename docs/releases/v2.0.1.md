# Diffyn v2.0.1

Diffyn 2.0.1 strengthens distribution and release verification without changing the nine tools, fourteen prompts, ten resources or six skills introduced in 2.0.0.

## Distribution

- Adds a Linux AMD64 container in GitHub Packages, built from the tested release binary and usable through local MCP process pipes.
- Runs the container as a non-root user with no network access or writable filesystem during protocol tests.
- Records binary and packaging revisions separately and signs container provenance.
- Checks the container base for high and critical vulnerabilities and keeps its digest under dependency monitoring.

## Release controls

- Requires each pull request to reserve a higher, unused version and carry a matching immutable candidate tag.
- Validates manifests, lockfiles, citation metadata, release notes and installation examples together.
- Creates the stable tag and publishes from the verified main commit after the required checks succeed.
- Prevents replacement of versioned container content and keeps `latest` tied to the latest verified stable release.
- Documents recovery for interrupted publication, package visibility and release verification.

## Engineering and maintenance

- Adds separate coverage measurements for Rust, Python and JavaScript, each with an 80% minimum.
- Compares executable bytes from two clean Linux builds and retains the verification reports.
- Expands regression tests for release integrity, container boundaries, version ordering and DCO validation.
- Adds focused pull-request labels and explicit release milestones.
- Documents governance, contribution requirements, test policy and the next year's roadmap.

The release does not add runtime network calls, storage or telemetry. Existing 2.0.0 MCP configurations and tool requests remain compatible.
