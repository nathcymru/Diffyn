# Diffyn v2.0.3

Diffyn 2.0.3 improves contributor setup, repository security configuration and documentation accuracy. Runtime tool interfaces remain compatible with 2.0.2.

## Contributor setup

- Add an optional development container with pinned Rust and Node.js images, a non-root user and documented manual checks.
- Explain Codespaces quotas, local use and DCO certification without provisioning hosted development time or prebuilds.
- Clarify how sign-offs certify submitted work and how GitHub's squash-merge identity changes differ from PR commit validation.

## Repository controls

- Document the full repository settings baseline, active branch and tag rules, app permissions and optional services.
- Permit the two trusted metadata workflows under a scoped Actions event policy ahead of GitHub's December restriction.
- Limit actions to approved publishers while preserving full commit SHA pinning.
- Restrict Pages deployments to `main`, remove administrator bypass and align security check reporting with the existing merge rule.
- Keep development-dependency alerts visible for explicit triage.
- Add pinned Harden-Runner network auditing to the Linux repeatability job, with its public telemetry and free-plan boundaries documented.

## Documentation accuracy

- Correct current capability descriptions, clarity-analysis coverage and checklist-window explanations.
- Explain the response-checking heuristics and input limits precisely.
- Verify request examples against the real MCP process and retain text alternatives for the three architecture diagrams.

Repository settings are enforced on GitHub separately from the source release. The settings guide records their reviewed configuration and the checks needed when they change.
