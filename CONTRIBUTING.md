# Contributing to Diffyn

Start with a small, concrete problem and an example of the desired behavior.
Use synthetic or redacted examples. Do not publish personal health details,
private conversations, API keys, or other people's data in issues or pull requests.

Changes should preserve user agency, explicit preferences, meaning, and exact
values. Neurotype labels are not a proxy for intelligence or communication
preferences. A shorter response is not automatically a better response.

For code changes, run the checks in [the engineering guide](docs/engineering.md).
Add regression cases for actual failures, especially information loss, Unicode,
numbers, conditions, code, privacy, and invalid inputs. Keep stdout reserved for
MCP and avoid input-bearing logs. Document known limits.

For prompt or resource changes, provide primary sources and distinguish evidence
from product decisions. Write original summaries; do not copy full articles or
third-party guides. Involve neurodivergent users in evaluation without requiring
diagnostic disclosure. User feedback matters alongside automated checks.
